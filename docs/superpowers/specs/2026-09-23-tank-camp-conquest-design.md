# 营地坦克割据 — 设计说明

- 日期：2026-09-23
- 状态：待用户审阅
- 工作标题：营地坦克割据（可改名）
- 平台：浏览器（桌面 + 手机）

## 1. 一句话

常驻开启的浏览器俯视坦克战：玩家以营地为核心割据扩张；攻破他人营地核心即占领该营；名下所有营地尽失才出局；出局后展示本轮成绩并写入浏览器本地，再开或刷新则作为新玩家重新加入。

## 2. 设计目标

- 保留经典坦克大战的移动与射击手感（四向、炮弹、可破坏地形）。
- 用「吞营建国」制造大乱斗与割据感，而不是传统一局一开的缩圈大逃杀。
- 打开网页即可玩，不强迫注册。
- 第一版验证核心循环是否好玩，再考虑扩到约 100 营规模。

## 3. 核心规则（已锁定）

### 3.1 营地与胜负

- 每个玩家以营地为核心单位；营地有可被摧毁的**核心**。
- **坦克是消耗品**：被击毁后可重生，不直接导致出局。
- **出局条件**：玩家名下**所有**营地的核心均被他人攻破后，该玩家本轮结束。
- **占领规则**：玩家 A 攻破玩家 B 某座营地的核心后，该营地所有权立即转给 A。A 可同时拥有多座营地。
- 不存在「无营游牧」状态：最后一座营失去的瞬间即出局。

### 3.2 重生

- 坦克被毁后，在「仍属于该玩家且核心仍在」的营地中**均匀随机**选一座重生。
- 重生附带短暂无敌（约 1–2 秒），避免刷脸即死。
- 不提供手动选营或「就近营」优先，以抑制多营玩家的精确飞营防守。

### 3.3 新人入场

- 打开页面后自动加入当前可进入的房间。
- 系统分配一座**空置营地**作为起点。
- 新分配营地的核心享有 **30–60 秒**不可被摧毁的保护期（坦克仍可被攻击）。
- 保护期结束后与其他营地同等可被攻占。

### 3.4 冲突驱动（不缩圈）

- 地图**不**使用毒圈/强制缩图。
- 冲突由三类内容驱动：
  1. **中立资源点**：油井、弹药库、修车点等，提供持续或拾取补给。
  2. **定时空投**：全图可感知的落点，投放高价值物资。
  3. **攻城补给**：拆核心的高效手段（攻城弹等），主要来自中立争夺与空投，而非在家挂机刷取。
- 设计意图：永久龟缩拆不动别人；要扩张必须出门抢攻城资源。

### 3.5 物资与成长（轻量）

第一版物资**几乎不改变坦克形态**，只改变弹药与防护：

| 类型 | 作用 | 获取 |
|------|------|------|
| 普通弹 | 打坦克、拆软墙 | 营地补给、小资源点 |
| 维修包 | 恢复护甲/底盘 | 营地、修车点 |
| 轻护甲板 | 可被打掉的外层护甲（有叠加上限） | 资源点、空投 |
| 攻城弹 | 对营地核心高伤；对坦克效果一般或偏弱 | 中立争夺、空投 |
| 拆墙高爆（可选） | 快速打开进攻路线 | 空投或中立点 |

明确不做：换车型、天赋树、永久局外成长树（第一版）。

### 3.6 个人节奏与房间寿命

- **无全场统一倒计时**；房间常驻，人来即玩。
- **个人一轮**目标体感约 **8–12 分钟**（从入场到出局的常见时长），通过核心脆度、攻城弹频率、地图密度调节，而非强制毒圈。
- 若后期多营玩家过多导致拖时间，第一版采用一种**软加压**（仍不缩圈）：当房间内仍存活的玩家营地总数降至阈值阈值（实现时默认 ≤8）时，提高空投中攻城弹比例。「公开标记占地第一为荣誉目标」留到后续版本。

### 3.7 结算与本地记录

出局瞬间展示：

- 本轮存活时长
- 曾拥有的最大营地数 / 当前被消灭时的营地相关统计
- 击毁坦克数、攻占营指数
- 相对房间的表现描述或简易名次（见 3.8）

写入浏览器 `localStorage`（或同等本地存储）的建议字段：

- 最长存活
- 单轮最大占地数
- 累计攻占营数、累计击毁
- 最近若干轮简史（可选，限条数）

再开或刷新：本轮状态清零，以新玩家身份重新分配空营；本地「历史最佳」可保留。

### 3.8 排名含义（常驻房）

因房间不统一结束，「全场最后一人」不是第一版主结算。

第一版采用：

- **本轮成绩面板**（主）
- **本地历史最佳**（主）
- 房间内可选的实时榜（占地数 / 击毁数），仅作展示，不作为强制段位

## 4. 第一版范围

### 4.1 规模

- **单房固定 32 个营地坑位**（位置预置在地图上；空置则可分配给新人或人机）。
- 房间满员后，新玩家进入**新房间**（规则相同）。
- 房间真人过少时，可用**简单人机**垫场（弱 AI：巡逻、争夺近点、低概率攻营）；人机可占据营地，被玩家攻破则营归玩家。

### 4.2 必做

- 俯视坦克移动与射击；砖墙可毁、钢墙难毁或不可毁；基础地形（空地/水/草等至少各一，草可作掩体）。
- 营地核心、保护期、毁核易主、多营归属、全丢出局。
- 己方营随机重生 + 短无敌。
- 至少一类中立资源点 + 攻城弹 + 一种空投。
- 桌面键盘 + 手机触控两套输入。
- 出局面板 + 本地成绩存储。
- 游客进房（自定义昵称即可，不强迫账号）。

### 4.3 明确不做（第一版）

- 真·100 人同屏单房
- 跨房战争、世界地图
- 账号体系、皮肤商城、支付
- 复杂车型/配件成长树、正式同盟/公会
- 精致观战与录像系统
- 匹配段位与赛季

### 4.4 成功标准

第一版「做对了」的判据：

1. 陌生人进房后 1 分钟内能理解「守营 / 抢弹 / 拆核占地」。
2. 多营玩家明显更强，但随机重生导致边境难守，出现有来有回的割据，而不是一人永占全图。
3. 桌面与手机都能完成完整一轮（入场 → 交战 → 出局 → 看成绩 → 再开）。
4. 单房约 32 营时，主流设备上操作仍可接受（允许用视野裁剪优化）。

## 5. 操作与界面

### 5.1 桌面

- 移动：方向键或 WASD（**四向**，与经典坦克一致；同时只保留一个主方向）。
- 射击：空格或 J。
- 切换弹药（普通 / 攻城）：Tab 或数字键 1/2。

### 5.2 手机

- 左虚拟摇杆或四向键移动；右开火键；切弹键独立。
- **横屏优先**；竖屏可玩但小地图与摇杆需防遮挡。
- 触控按钮不得挡住坦克自机附近的主要交火区（可半透明）。

### 5.3 HUD（最小集）

- 当前弹药类型与攻城弹数量
- 名下营地数量
- 小地图：己方营、敌方营（可简化为色点）、中立点、空投
- 核心保护倒计时（仅自己受保护时）
- 出局结算大面板

## 6. 地图结构（第一版）

- 约 32 座营地大致均匀散布在地图外围或浅网格上，保证相邻营有可达进攻路线。
- 内圈设置中立资源带；中心可放 1 个高风险高回报点（争夺激烈）。
- 营地自带简易围墙/入口，核心置于相对内侧，降低「路过一枪偷拆」，鼓励破墙推进。
- 核心生命值与攻城弹单发伤害的配比目标：2–3 名有攻城弹的玩家协同，应能在约数十秒内拆掉一座无保护核心（具体数值实现阶段再调）。

## 7. 技术骨架（已锁定方向）

- **前端**：画布 / 轻量 2D 引擎（候选：Phaser 或 PixiJS）。
- **同步**：现成多人房间框架做**权威服务器**状态同步（候选：Colyseus）。
- **部署形态**：第一版单进程可多房间；每个房间独立状态。
- **同步原则**：
  - 服务器权威：命中、核心伤害、所有权变更只以服务器结果为准。
  - 客户端做预测与插值；对核心易主等关键事件以服务器广播为准做校正。
  - 视野裁剪：优先向客户端发送其附近实体，控制 32 营同房流量。

### 7.1 关键状态（逻辑模型）

- `Room`：地图、中立点、空投日程、玩家列表
- `Player`：昵称、拥有的 `campId[]`、坦克姿态与生命、背包弹药、本地会话 id
- `Camp`：槽位、所有者、核心生命、保护到期时间
- `Projectile` / 资源点拾取：短生命周期实体

所有权变更与出局必须在同一权威路径内原子处理（拆核 → 易主或出局 → 广播）。

## 8. 人机（第一版可选但建议有）

- 目的：垫场，不是做成高水平对手。
- 行为：在出生营附近游荡、偶发前往最近中立点、低概率对邻营开火；获得攻城弹后才尝试拆核。
- 真人加入时可替换人机占用的营位（实现时可「踢最弱人机」或「人机营转为空营再分配」——第一版采用：**优先分配空营；无空营时回收一个人机营分给新人**）。

## 9. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 多营雪球一人占满图 | 随机重生；攻城资源在中立区；核心需持续火力；可选荣誉目标 |
| 开局被秒 | 30–60 秒核心保护 |
| 双端拖工期 | 同一套输入映射；UI 组件先简后美 |
| 32 人性能 | 视野裁剪、子弹与特效上限、人机逻辑降频 |
| 常驻房「排名」难定义 | 第一版主打本轮成绩 + 本地最佳，不做强制全局段位 |

## 10. 以后可扩展（非第一版）

- 扩到 48–64 或约 100 营单房
- 账号与化妆品
- 正式同盟、观战、赛季
- 更多地形与炮弹种类（仍建议保持「不变形坦克」的产品克制）
